Common web vulnerabilities

SQL Injection

Injecting malicious SQL syntax into application input so the resulting database query behaves differently than intended. Can potentially allow reading, modifying, or deleting database data.

          
          username = input("Username: ")
          password = input("Password: ")

          query = f"SELECT * FROM users WHERE username = '{username}' AND password = '{password}'"

If you put something like this in the passwords place:

          
          ' OR '1'='1' --

The result will be: 

          
          SELECT * FROM users
          WHERE username = '' OR '1'='1' --' AND password = 'anything'
Cross Site Scripting

Injecting attacker-controlled JavaScript or HTML into a web page so it executes in another user's browser. Common types include reflected, stored, and DOM-based XSS.

Imagine a website displaying web content directly on the site:

          
          comment = request.form["comment"]
          return f"{comment}"

if the application places untrusted input directly into HTML, an attacker could submit:

          
          <script>alert("XSS")</script>
Cross Site Request Forgery

Tricking a victim's browser into sending an authenticated request to a web application without the victim intentionally performing the action. Usually relies on the browser automatically sending authentication cookies.

          
          POST /transfer
          Content-Type: application/x-www-form-urlencoded

          to=attacker&amount=1000

If the application doesn't verify that the request was intentionally generated by its own site, an attacker could create a malicious page containing a form

Broken Access Control

A user can access functionality or data that they should not be authorized to access. This includes privilege escalation and accessing another user's resources.

Insecure Direct Object Reference

An application exposes an identifier for an object, such as a user ID or document ID, without properly checking authorization. Changing the identifier may expose another user's data.

Command Injection

Attacker-controlled input becomes part of an operating-system command executed by the server. Successful exploitation can allow arbitrary commands to run with the application's privileges.

Path Traversal

Manipulating file paths using sequences such as ../ to escape the intended directory. This can allow access to sensitive files outside the application's normal file-access location.

Local File Inclusion

An application allows an attacker to influence which local file is loaded or processed. Depending on the application, this can expose sensitive files or sometimes lead to code execution.

XML External Entity

Exploiting an XML parser that allows external entities to make the server process unintended external or local resources. This can potentially expose files or make server-side network requests.
